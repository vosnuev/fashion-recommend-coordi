# 착장 분석 API 연동 — 작업 안내

**한 줄 요약**: 지금 "내 착장 분석" 화면은 사진을 올려도 **미리 적어둔 고정 결과**를 보여준다.
이걸 **진짜 백엔드 분석 결과**로 바꾸는 작업이다.

---

## 1. 지금 화면이 어떻게 돼 있나

파일 하나다 → **`mobile/src/app/outfit-review.tsx`**

흐름은 이미 다 만들어져 있다:

```
사진 고르기 → [분석하기] → (0.7초 기다림) → 결과 화면
```

문제는 가운데다. 지금은 서버를 부르지 않고 `setTimeout` 으로 0.7초 쉬었다가
파일 맨 위에 적힌 고정 문구(`FOUND_ITEMS`)를 보여준다. 어떤 사진을 올려도 결과가 같다.

```ts
// outfit-review.tsx 현재 코드
const analyze = () => {
  setAnalyzing(true);
  setTimeout(() => {          // ← 여기를 실제 API 호출로 바꾸면 된다
    setAnalyzing(false);
    setComplete(true);
  }, 700);
};
```

**사진 고르는 부분은 손 안 대도 된다.** `lib/pickItemPhoto.ts` 의
`pickOutfitPhoto()`(앨범) · `takeOutfitPhoto()`(카메라)가 이미 붙어 있다.

## 2. 붙일 API

### Swagger에서 직접 보기

<https://qualifications-database-additional-achieved.trycloudflare.com/api/docs/#/Outfit%20Analysis/outfit_analysis_create>

> ⚠️ 이 주소는 팀 임시 서버(cloudflare 터널)라 **가끔 바뀐다.** 안 열리면 팀에 최신 주소를 물어볼 것.

### 보내는 것

`POST /api/v1/outfits/analyze/` — **multipart/form-data** (JSON 아님)

| 필드 | 필수 | 내용 |
|---|---|---|
| `image` | ✅ | 코디 사진. JPEG·PNG·WebP만, 15MB 이하 |
| `lat` | | 위도 (날씨 반영용) |
| `lon` | | 경도 |

- `lat`·`lon`은 **둘 다 넣거나 둘 다 빼야 한다.** 하나만 넣으면 400 이 난다.
- 생략하면 서버가 서울 기준으로 처리한다. 지금 앱은 위치 권한을 안 쓰므로 **일단 빼고 보내면 된다.**

### 로그인 여부

**로그인 안 해도 호출된다.** (둘러보기에서 바로 쓸 수 있게 열어둔 API다)
다만 로그인 상태면 저장된 추구미·체형을 반영해 결과가 더 개인화되니, **토큰이 있으면 같이 보내는 게 좋다.**

### 받는 것

```
{
  "status": "completed",
  "evaluation": {
    "overall_score": 0~100 사이 점수,
    "summary": "총평 한 문단",
    "strengths": ["잘한 점", "..."],          // 문자열 배열
    "weather_comment": "날씨 관련 한마디",
    "personalization_comment": "취향 반영 한마디",
    "styling_tips": ["이렇게 해보세요", "..."]  // 문자열 배열
  },
  "context": {
    "weather": 날씨 정보,
    "personalized": true/false,   // 개인화가 실제로 반영됐는지
    "used_pursuit": true/false,   // 추구미를 썼는지
    "used_body": true/false       // 체형을 썼는지
  }
}
```

`context` 는 화면에 꼭 안 보여줘도 된다. 다만 `personalized: false` 면
"로그인하면 취향까지 반영해드려요" 같은 안내를 띄우기 좋다.

### 실패할 때

| 코드 | 뜻 | 화면에서 할 일 |
|---|---|---|
| 400 | 사진 형식·용량이 안 맞음 / lat·lon 한쪽만 보냄 | 다시 고르라고 안내 |
| 415 | multipart 로 안 보냄 | 코드 실수 |
| 503 | 서버 쪽 AI 호출 실패 | "잠시 후 다시" 안내 + 재시도 버튼 |

분석은 AI를 거쳐서 **몇 초 걸릴 수 있다.** 지금 있는 "분석 중" 상태를 그대로 쓰되,
타임아웃을 넉넉히 잡는 게 좋다.

## 4. 앱에서 참고할 코드 — **이미 비슷한 걸 해놨다**

**`mobile/src/lib/wardrobeApi.ts` 의 `uploadWardrobePhoto()`**

옷장에 옷 사진 올리는 함수인데, **사진을 multipart 로 서버에 보내는 것**이 똑같다.
이걸 본 삼아 엔드포인트·필드명·응답 처리만 바꾸면 된다.

### 여기 함정이 있어서 꼭 읽어야 한다

**① 인터넷에서 흔히 보는 방식이 우리 환경에선 안 된다**

```ts
form.append('image', { uri, name, type });   // ❌ 이렇게 하면 실패한다
```

RN 예제 대부분이 이 형태인데, 지금 Expo 버전에서는 거부당한다
(`Unsupported FormDataPart implementation`). `uploadWardrobePhoto` 가 쓰는
`expo-file-system` 업로드 방식을 따라가면 된다.

**② 웹과 앱이 방식이 다르다**

- **웹**: 사진을 Blob 으로 만들어 `FormData` 에 담는다
- **앱(iOS/Android)**: `expo-file-system` 의 파일 업로드를 쓴다

`uploadWardrobePhoto` 는 `Platform.OS === 'web'` 으로 갈라서 둘 다 처리한다. 같은 구조로 가면 된다.

**③ 앱 경로는 인증 헤더를 직접 붙여야 한다**

파일 업로드는 우리 공용 `apiClient` 를 안 거쳐서, 토큰이 자동으로 안 붙는다.
`uploadWardrobePhoto` 가 `getAccessToken()` 으로 직접 붙이고 있으니 그대로 따라하면 된다.
(착장 분석은 토큰 없어도 되지만, 있으면 결과가 좋아진다)

> ℹ️ `mobile/src/state/measure.ts` 의 체형 사진 업로드는 **옛날 방식(①)이 남아 있다.**
> 참고 대상으로 삼지 말 것. (별도로 손봐야 하는 건이다)

## 5. 시작 전 준비

브랜치를 받은 뒤 **한 번만** 하면 된다.

```bash
cd mobile
cp .env.example .env
npm install
```

`.env` 는 저장소에 없어서 **직접 만들어야 한다.** 만들고 나서
`EXPO_PUBLIC_API_URL` 에 **팀 서버 주소를 넣어야 한다.**
안 넣으면 `localhost:8000` 으로 붙어서 아무것도 안 된다.

```
EXPO_PUBLIC_API_URL=https://...(팀에 물어볼 것)
```

실행:

```bash
npx expo start --web      # 브라우저로 빠르게 확인
```

착장 분석 화면 주소는 `/outfit-review` 다. 로그인 없이 들어갈 수 있다.

## 6. 다 됐는지 확인하는 법

- [ ] **다른 사진을 넣으면 다른 결과**가 나온다 (지금은 뭘 넣어도 같은 결과)
- [ ] 사진 없이 [분석하기]를 못 누른다
- [ ] 서버가 죽었을 때 화면이 멈추지 않고 안내가 뜬다
- [ ] 로그인 없이도 동작한다
- [ ] `npx tsc --noEmit` 이 오류 없이 끝난다
