## 5. 실행 방법

### 5.1 백엔드

```bash
# 로컬 인증 우회가 필요할 때
infisical run --env=dev -- env DJANGO_SETTINGS_MODULE=config.settings.swagger_noauth \
  docker compose up -d --build api
```

- `api/` 수정 후에는 **반드시 `--build`** (코드가 볼륨 마운트가 아니라 이미지에 빌드된다)
  실제로 이걸 빼먹고 옛 이미지로 테스트를 돌려 결과를 잘못 읽은 적이 있다.
- `swagger_noauth`는 **런타임 전용**이다. 테스트는 반드시 `config.settings.dev`로 돌린다 (§5.4)

### 5.2 프론트

```powershell
.\run-mobile.ps1     # EXPO_PUBLIC_API_URL=http://localhost:8000 + expo web 8081
```

`EXPO_PUBLIC_*` 는 **번들 빌드 시점에 값이 박힌다.** 주소를 바꾸려면 Expo 를 다시 띄워야 한다.

> ⚠️ Expo 개발 서버는 **사용자 터미널에서 직접** 띄워야 한다. 에이전트 백그라운드로는 유지되지 않는다(두 번 시도, 두 번 죽음).

#### 카카오 공유를 다시 시험하게 될 때 알아야 할 것 (2026-08-14 조사 결과)

카카오 검증은 이번에 **접었다.** 관련 스크립트·진단화면은 전부 삭제했다(§6). 다시 붙일 때 같은 길을 헤매지 않도록 알아낸 것만 남긴다.

| 항목                    | 알아낸 것                                                                                                                                                                                                                                                       |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 왜 https 가 필요한가    | 카카오 JS SDK·클립보드·공유 API 는**보안 컨텍스트 전용**이다                                                                                                                                                                                            |
| `http://localhost`    | ✅**보안 컨텍스트로 인정된다** → PC 확인은 터널 없이 가능. 카카오 콘솔에 `http://localhost:8081` 을 등록하면 되고, 이 주소는 안 바뀌니 **한 번만** 등록하면 된다                                                                                 |
| `http://<PC-IP>:8081` | ❌ 보안 컨텍스트가 아니다 → 휴대폰 확인에는 https 터널이 필요하다                                                                                                                                                                                              |
| 콘솔 등록 위치          | **`앱 설정 > 플랫폼 > Web > 사이트 도메인`**. `제품 설정`의 Redirect URI 는 JS SDK 공유와 **무관**하다                                                                                                                                          |
| 앱·API 오리진          | nginx 로 한 오리진에 합치면 mixed content·CORS 가 없고 등록 도메인도 하나다. 그때는`EXPO_PUBLIC_API_URL` 과 `EXPO_PUBLIC_INVITE_BASE_URL` 이 **같은 값인 게 정상**이다 (라우팅: `/api`·`/media` → 8000, 나머지 → 8081 + WebSocket 업그레이드) |
| trycloudflare           | 주소가**매 실행마다 바뀐다** → 카카오 콘솔 재등록이 매번 필요. 고정하려면 Cloudflare 계정 + 소유 도메인(named tunnel)                                                                                                                                    |
| 실측으로 배제한 것      | JS 키 번들 적재 ✅ · 키 이름`EXPO_PUBLIC_KAKAO_JAVASCRIPT_KEY` ✅ · 카카오 CDN 도달 ✅ · 썸네일 도달 ✅                                                                                                                                                    |
| 남은 유력 원인          | 팝업 차단(코드는 수정 완료, §2-11)과 콘솔 도메인 미등록 —**둘 다 화면에서 확인 못 했다**                                                                                                                                                                |

> ⚠️ Expo 개발 서버는 **사용자 터미널에서 직접** 띄워야 한다. 에이전트 백그라운드로는 유지되지 않는다(두 번 시도, 두 번 죽음).

### 5.4 테스트 — 설정 모듈을 반드시 바꾼다

```bash
docker compose exec -T -e DJANGO_SETTINGS_MODULE=config.settings.dev api \
  python manage.py test apps.wardrobe apps.recommend --noinput
```

- `-e DJANGO_SETTINGS_MODULE=config.settings.dev` 를 **빼면 안 된다.** 컨테이너가 `swagger_noauth`로 떠 있으면 인증 테스트 **27개가 전부 에러**난다.
  이유: `swagger_noauth`가 등록하는 `AutoLoginAuthentication`은 `DEBUG=True`가 아니면 일부러 예외를 던지는데([authentication.py:39](../api/apps/users/authentication.py:39)), Django 테스트 러너는 항상 `DEBUG=False`를 강제한다. 코드 버그가 아니다.
- `--noinput` 은 이전 실행이 남긴 `test_fashion_db`를 묻지 않고 지운다. `-T`(TTY 없음)로는 프롬프트에 답할 수 없다.
- `--keepdb` 는 마이그레이션을 건드리지 않았을 때만. 스키마가 바뀌면 옛 스키마로 테스트해 엉뚱하게 통과한다.

**현재 결과 (✅ 2026-08-14 원복 후 재빌드하고 실측): 382개 중 376개 통과, 6개 실패.** `apps.wardrobe`는 전부 통과.

> 개수가 381 → 382 로 늘어난 이유: 원복으로 Gemini 테스트 1개가 빠졌지만, **재빌드 덕분에 작업트리에만 있던 `tests_item_retriever.py` 의 새 테스트들이 그제야 이미지에 들어왔다.** 그 전 실행들은 옛 이미지를 돌린 것이다.
