## 1. 구현 성과 요약

오늘 모바일 화면의 Mock(시뮬레이터 가짜 데이터)로만 기획되어 돌고 있던 **공유 옷장 기능**을 백엔드 비즈니스 로직(DB 저장, 24시간 만료, 방장 위임 등)과 연결하여 **실시간 E2E(End-to-End) 연동 개발을 최종 완수**하였습니다.

이를 통해 가상 시나리오가 아니라, 실제로 6자리 암호코드를 발급하고 입력함으로써 방을 개설 및 가입할 수 있는 서비스의 핵심 유연 기틀이 마련되었습니다.

---

## 2. 세부 비즈니스 정책 및 반영 내용

1. **공유 옷장 개설 & 24시간 만료**:
   * 영문 대문자+숫자 조합의 **6자리 난수 초대코드**가 생성됩니다.
   * 초대코드는 생성 시점부터 **24시간 동안만 유효**하며, 만료 시간이 지난 코드로 참여를 시도하면 백엔드가 검증하여 화면 하단에 에러 Toast 알림을 띄우며 차단합니다.
2. **초대코드 재발급 (Refresh)**:
   * 방장(`owner`) 권한을 가진 유저만 코드를 재생성할 수 있으며, 기존 코드는 즉시 파기되고 새로운 24시간짜리 핀코드가 갱신 발급됩니다.
3. **방장 퇴장 시 자동 방장 권한 위임**:
   * 초대한 사람이 방을 나가도 공유방이 깨지지 않고 온전히 유지됩니다.
   * 남은 멤버가 1명이라도 있으면 가입일이 가장 빠른 멤버가 새로운 방장(`owner`)으로 자동 변경(승격)됩니다. 참여자가 0명이 될 때 비로소 방이 폭파됩니다.
4. **퇴장 시 아이템 처리 분기 (사용자 선택)**:
   * **옵션 A**: 내가 등록한 옷 아이템을 모두 지우고 퇴장 (`delete_my_items = True`)
   * **옵션 B**: 내 옷 데이터는 공유방에 기여로 그대로 보존하고 몸만 퇴장 (`delete_my_items = False`)

## 3. 데이터베이스 적재 테이블 명세

공유 옷장 액션 시 아래 3개 테이블에 데이터가 영구 적재 및 관계 매핑됩니다:

* **`shared_wardrobe_room` (공유방)**: 방 이름, 고유 6자리 핀코드, 24시간 만료일시 저장
* **`shared_wardrobe_member` (참여 멤버십)**: 사용자 권한 분기 (`owner` / `member`), 가입 일시 매핑
* **`shared_wardrobe_item` (공유된 옷들)**: 등록 유저 ID(SET_NULL 지원), 원본 개인 옷장 아이템 매핑, 대여 상태(`available`/`borrowed`/`private`) 관리

## 5. 실시간 시연 가이드 (1, 2, 3 단계)

1. **백엔드 서버 켜기**:
   * `infisical run --env=dev -- docker compose --profile api up -d --build` 로 로컬 컨테이너 가동 후, `docker compose stop weather-collector outfit-worker`로 필요 없는 컨테이너는 종료하여 자원을 보존합니다.
2. **모바일 앱 구동**:
   * `mobile` 폴더에서 `npm run dev`를 실행하고 브라우저 시뮬레이터나 Expo Go로 접속합니다.
3. **공유 옷장 시나리오 수행**:
   * [공유 옷장] 탭에서 **[옷장 만들기]**를 누르면 백엔드에 6자리 초대코드와 멤버십이 실시간 등록되어 화면에 출력됩니다.
   * 만료된 코드나 임의의 틀린 코드를 치면 백엔드의 24시간 검증기를 거쳐 **"유효하지 않거나 만료된 초대 코드입니다"** Toast가 정상 표출됩니다.
