# 골든셋 범위 검증 리포트

> **역사 자료**: 2026-08-10 작업 시점의 범위 검토다. 이후 입력 항목과 규칙이 바뀌었으므로 현재 상태는 최신 코드와 [`README.md`](../../../README.md)를 우선한다.

> **결론 먼저**: 색상 규칙은 **문서만 비대해졌고 코드에 쓰이는 핵심은 적절**합니다.
> 체형 규칙은 **현재 쓸 수 있는 건 가로축 1개뿐**이고, 나머지 3축은 입력 자체가 없어서 실제로 과한 게 아닙니다.
> 단, **이미지/배치 파일들이 불필요하게 레포를 무겁게** 만들고 있습니다.

## ① 색상 규칙 (`color_rules.json` — 94.8KB)

| 항목 | 실제 값 | 판단 |
|---|---|---|
| 색상 수 | 18색 (v2 팔레트) | ✅ 적절 — 한국 패션 앱 기준 충분 |
| pair_grades | **306쌍** (양방향 포함) | ⚠️ 숫자가 커 보이지만 18×18÷2 = 153쌍의 **양방향** = 306, 실제 고유 조합은 153 |
| 등급 분포 | 권장 250 / 주의 38 / 허용 14 / 기피 4 | ✅ 정상 — 기피가 4쌍밖에 없어 하드필터 부담 없음 |
| 생성 방식 | R1~R6 규칙 기반 자동 생성 (`build_color_rules.py`) | ✅ 수기 아님, 재현 가능 |
| 파일 크기 | 94.8KB | ⚠️ 크긴 하지만 `color_taxonomy_map.json`(5.2KB)만 코드에서 실제로 import됨 |

**⚠️ 실제 과한 부분**: `color/images/outfits/` 하위 배치 JSON 파일들 (batch_00~batch_28 등 ~28개)
- 이 파일들은 이미지 생성 입력용이지 추천 로직에 쓰이지 않음
- 레포에 들어갈 필요 없이 로컬에만 있으면 됨

## ② 체형 규칙 (`body_fit_rules.json` — 11.9KB)

| 축 | 상태 | 실제 사용 가능? |
|---|---|---|
| 가로축 — 5대 실루엣 (shoulder/waist/hip) | ✅ measurable | **지금 당장 쓸 수 있음** |
| 세로축 — 상체:하체 비율 | ❌ NOT_measurable_yet | 입력 컬럼 없음, 기본값 `balanced` 고정 |
| 세로축 — 목 길이 | ❌ NOT_measurable_yet | 입력 컬럼 없음 + neckline 태그도 없음 |
| 세로축 — 허벅지:종아리 | ❌ NOT_measurable_yet | 컬럼은 있지만 **둘레라서 쓰면 안 됨** (가장 위험) |

**판단**: 규칙 자체는 **과하지 않음** — 오히려 나머지 3축은 입력이 없어서 지금 당장 동작하지 않고, 그게 JSON에 명시까지 되어 있음. 단, **세로축 3종을 문서와 Confluence에서 너무 강조**하다 보니 "다 구현된 것처럼" 보이는 게 문제.

## ③ 레포 무게 문제

```
golden-set/
├── color/images/outfits/
│   ├── _batches/          ← batch_00~28 JSON (이미지 생성 입력 — 레포 불필요)
│   ├── curated/_batches/  ← 동일
│   ├── practical/_batches/← 동일
│   └── personal_color/    ← 동일
└── body/images/
    └── comparison/        ← PNG 57개 (이미지는 Git LFS 또는 별도 관리 권장)
```

배치 JSON 파일들 총합 ~30개는 추천 시스템 실행에 필요 없음.

## 🔧 권장 액션 (우선순위)

1. **`color/images/outfits/_batches/`** → `.gitignore` 추가 또는 삭제 (추천 로직과 무관)
2. **세로축 3종** → 문서/Confluence에서 "현재 미사용(입력 없음)" 상태를 명확히 표기

4. **가로축만으로 먼저 연결** → `filter_rules.py` 구현 시 `width_rules`만 활성화, 나머지 축은 `default_when_unknown` 처리
